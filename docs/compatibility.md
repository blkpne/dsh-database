### TLS

Oracle 的 IPv6 TCPS 连接依赖 Node 原生的证书身份检查。Node 24.18/24.19 存在合法 IPv6 IP SAN 被拒绝的上游回归；在 24.19 上，Oracle 驱动 7.0.1 和 26.0.0 均返回 `NJS-506`，没有发送受 TLS 保护的 Oracle 协议数据。仅升级驱动不能解决此问题。[Node 24.20.0](https://nodejs.org/en/blog/release/v24.20.0) 和 [22.23.4](https://nodejs.org/en/blog/release/v22.23.4) 已包含 IPv6 SAN 匹配修复。

2026-11-07，未发布候选在 Linux x64、Node 22.23.4 和 24.22.2 下各通过 65 例协议检查，包含 Oracle 的 IPv6 正反路径；24.22.2 另对照了 Oracle 驱动 7.0.1 与 26.0.0。正确证书允许发送加密协议数据，错误 IP/DNS 身份、过期或不受信任证书在协议数据前拒绝。这些协议监听器不提供 Oracle 数据库认证或查询。

需要 Oracle IPv6 TCPS 时，应使用包含上述修复的 Node 补丁版本，并在目标数据库验证认证与查询。无法升级时，只能改用证书明确覆盖、可实际到达的 DNS 名称或 IPv4 地址；不得关闭证书链或身份检查、替换校验主机名或弱化 DN 匹配。插件整体最低 Node 要求不因此改变，较早版本的 Oracle IPv6 支持不能据此推定。Linux 补验不等同于未发布候选的 Windows/macOS CI。

同日，SQL Server 2022 CU27（16.0.4295.3）、Tedious 20.3.6 在上述两版 Node 完成真实 TLS 登录与精确金额汇总。32 次证书/信任链检查覆盖正确 DNS/IPv4/IPv6 SAN，以及错误身份、过期与不受信任 CA；15 次独立不存在账户的对照结合服务端失败登录日志，验证证书拒绝发生在认证之前。IPv6 使用 `::1` 到所属容器 IPv4 发布端口的透明字节转发，TLS 在数据库终止，客户端仍校验 `::1`；这不代表 Docker IPv6 网络或远程拓扑验收。该补验补充下表的历史 SQL Server TLS 缺口。

Oracle 23.9.0.25.07、驱动 7.0.1 另完成真实 TCPS：Node 24.22.2 的 DNS/IPv4/IPv6 与 22.23.4 的 IPv6 均成功认证并查询合成数据的精确金额 `30.375`；不受信任 CA 被拒绝。相同数据库、钱包与 IPv6 转发路径在 24.19 下返回 `NJS-506`。服务器只启用单向 TLS，客户端保留证书链与身份检查；未测试客户端证书认证。真实 Oracle TCPS 的错误身份/过期证书仍只有上述协议检查证据，不能与 SQL Server 的真实负例矩阵混称。

| 引擎                         | 已完成                                                                                       | 本页不覆盖                    |

| MySQL / MariaDB / PostgreSQL | 真实数据库证书校验；正确 DNS/IP 身份，以及错误身份、过期、不受信任证书的拒绝；失败不降级明文 | 其他版本及部署拓扑            |

### 取消与部署范围

- PostgreSQL、MongoDB 已覆盖服务端在途操作终止与恢复。
- SQL Server、Oracle 的记录覆盖客户端取消，不包含一般性的服务端在途终止验收。
- 客户端取消、关闭连接与服务器停止计算是不同结果。具体实现和清理证据见[超时与取消](reference.md#超时与取消)。
- 本页验证范围不包含集群、故障转移和 MongoDB Atlas/SRV；表单支持 SRV 不代表相应部署方式经过验证。

## Web 与 Agent

2026-11-07，未发布候选在 Linux x64、Node 24.22.2、DSH Web 0.2.2-rc.1 上补验原生 DeepSeek Messages 与明确 Off：Agent 通过 inspect 发现合成 PostgreSQL 结构，再用 query 返回精确汇总 `30.375`；停用授权后数据库工具从 2 个变为 0，Agent 拒绝继续查询，未使用其他工具替代。没有使用 pi-ai Chat 替代路由，也未修改日常 Profile。

先前的 HTTP 500 曾在不含数据库工具的最小提供方请求中出现，本次官方最小默认/disabled/low 请求及宿主原生 Off 均成功，未复现 500。这支持继续使用当前原生路由，但不能确认服务端内部根因或保证故障不会再次出现；数据库连接器未为此增加供应商配置逻辑。此次未重跑此前全部浏览器交互、六库和在线质量场景。
